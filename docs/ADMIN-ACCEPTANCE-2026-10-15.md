## Завершено

- IndexedDB хранит версию формата, ключ owner/repo/branch/режим, время, ревизию, документ, исходную базу/head и один Blob на используемый новый файл. Документ и файлы фиксируются одной транзакцией. Временные URL и авторизация в запись не попадают.
- Единая история уведомляет очередь обо всех правках, в том числе форме, инспекторе и Undo/Redo. Снимок неизменяемый, записи последовательные, ожидающие версии объединяются. Старое завершение не объявляет новую правку сохранённой.
- При повторном входе можно восстановить незавершённые поля и изображения с новыми object URL и bytes для существующего GitHub.save. Увеличивается documentEpoch; история начинается заново. Исходные id сохраняются; случайные id старого JSON не дают ложного конфликта базы.
- Изменившаяся удалённая база показана явно. Две вкладки защищены сравнением ревизии в той же readwrite-транзакции, включая отмену черновика. Ошибки квоты/транзакции не заменяют предыдущую целую копию.
- Выход сохраняет работу, перечитывание отменяет её после подтверждения, импорт сохраняет новую версию. GitHub-ошибка сохраняет копию; успешное обновление ветки позволяет очистить её. Экспорт не публикует и не удаляет черновик.
- На мобильном экране панель команд больше не перекрывает редактор при прокрутке; кнопки образуют две колонки. Галерея имеет зоны нажатия от 44 px; длинные сообщения переносятся, фокус в медиатеке не обрезается. Диалоги учитывают высоту мобильного viewport. Направляющие стрелки Hero и панели нарисованы SVG и не зависят от отсутствующего символа в шрифте.

Имя/профессия капсом, интро, логотип с синей точкой, ткань, жидкая кнопка, scroll-анимации и зелёная лента сохранены. Контент и изображения портфолио не изменены.

## GitHub Pages и оставшийся внешний шаг

По публичной странице Actions подтверждён успешный [Deploy to GitHub Pages для 89404a5](https://github.com/suleyman-sheripov/design/actions/runs/38617923134), также успешен [pages build and deployment](https://github.com/suleyman-sheripov/design/actions/runs/38617919003). Workflow собирает main с базой `/design/`; приложение использует hash-маршрут кейса и читает обновляемый контент из raw.githubusercontent.com. Чтение реального raw JSON и всех пяти опубликованных превью вернуло HTTP 200; байты превью совпали с checkout по SHA-256.

Эта среда получает proxy **HTTP 403** от `suleyman-sheripov.github.io` и `api.github.com`. Git fetch/push и публичная страница Actions доступны. Поэтому проверка живых `/design/` и `/design/admin/`, настроек Pages через API и реальной авторизации/сохранения владельца не выполнена. Успешный прежний Actions не доказывает работу ещё не опубликованного кода этой ветки. Секреты не извлекались; присутствие GH_TOKEN само по себе не устанавливает право владельца.

Владельцу остаётся один безопасный приёмочный сценарий:

1. Создать отдельную ветку `qa/admin-acceptance` от рассматриваемой версии. Собрать приложение и скопировать `app/dist` в отдельный временный каталог `design/`. Только в этой копии `site-config.json` указать `content.branch = "qa/admin-acceptance"` и отдать её HTTP-сервером. Исходники и main не менять.
2. В `/design/admin/` временной копии ввести собственный fine-grained токен с Contents read/write **непосредственно в форму**. Изменить тестовый текст и превью, дождаться локального сохранения, reload и восстановить. Сохранить в GitHub; проверить один коммит с JSON + WebP **только в qa-ветке** и результат на публичной странице этой же тестовой копии, читающей qa-контент. Токен после reload не восстанавливается; без токена GitHub не даёт запись. Никаких тестовых текстов в main.
3. После обычного согласованного слияния/деплоя проверить реальный Pages: главную, `/design/admin/`, прямой адрес `#/work/beautylab` с reload, изображения и восстановление локального черновика. Проверить видимость только намеренного настоящего изменения контента; тестовую qa-ветку не сливать ради проверки.

Публичный адрес админки не закрытый вход. Клиент проверяет совпадение `/user.login` с owner и право push; GitHub дополнительно авторизует каждый запрос. Соавторы с правом записи сохраняют прямой доступ к репозиторию независимо от этой формы. Для режима «только владелец» права соавторов/приложений должны быть настроены самим владельцем; эта задача их не меняла.
