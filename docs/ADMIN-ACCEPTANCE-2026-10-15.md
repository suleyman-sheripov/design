## Завершено

- IndexedDB хранит версию формата, ключ owner/repo/branch/режим, время, ревизию, документ, исходную базу/head и один Blob на используемый новый файл. Документ и файлы фиксируются одной транзакцией. Временные URL и авторизация в запись не попадают.
- Единая история уведомляет очередь обо всех правках, в том числе форме, инспекторе и Undo/Redo. Снимок неизменяемый, записи последовательные, ожидающие версии объединяются. Старое завершение не объявляет новую правку сохранённой.
- При повторном входе можно восстановить незавершённые поля и изображения с новыми object URL и bytes для существующего GitHub.save. Увеличивается documentEpoch; история начинается заново. Исходные id сохраняются; случайные id старого JSON не дают ложного конфликта базы.
- Изменившаяся удалённая база показана явно. Две вкладки защищены сравнением ревизии в той же readwrite-транзакции, включая отмену черновика. Ошибки квоты/транзакции не заменяют предыдущую целую копию.
- Выход сохраняет работу, перечитывание отменяет её после подтверждения, импорт сохраняет новую версию. GitHub-ошибка сохраняет копию; успешное обновление ветки позволяет очистить её. Экспорт не публикует и не удаляет черновик.
- На мобильном экране панель команд больше не перекрывает редактор при прокрутке; кнопки образуют две колонки. Галерея имеет зоны нажатия от 44 px; длинные сообщения переносятся, фокус в медиатеке не обрезается. Диалоги учитывают высоту мобильного viewport. Направляющие стрелки Hero и панели нарисованы SVG и не зависят от отсутствующего символа в шрифте.

Имя/профессия капсом, интро, логотип с синей точкой, ткань, жидкая кнопка, scroll-анимации и зелёная лента сохранены. Контент и изображения портфолио не изменены.

## Что осталось перед обновлением действующего сайта

[PR №1](https://github.com/suleyman-sheripov/design/pull/1) содержит изменения автосохранения и polish. После разрешения владельца на обновление main: проверить CI, объединить **этот PR**, дождаться Deploy to GitHub Pages и проверить новую админку на реальном Pages — reload/восстановление с изображением. До этого момента новый код нельзя считать опубликованным. Ветка qa содержит только тестовые данные и в публикации участвовать не должна.

Для обычной работы владелец вводит свой fine-grained токен Contents read/write прямо в форму `/design/admin/`, как описано в [ADMIN.md](ADMIN.md). В чат, исходники или хранилище браузера токен не передаётся.

Проверка полностью анонимной записи из этой машины не считается выполненной: платформенный GitHub-прокси авторизовал даже запрос curl без явного Authorization (проверялось только no-op обновление qa-ref на тот же SHA). Это существующая авторизация облачной сессии, а не публичный доступ на запись. Проверка отказа чужому login и отсутствию push остаётся подтверждённой тестами адаптера.

Публичный адрес админки не закрытый вход. Клиент проверяет совпадение `/user.login` с owner и право push; GitHub дополнительно авторизует каждый запрос. Соавторы с правом записи сохраняют прямой доступ к репозиторию независимо от этой формы. Для режима «только владелец» права соавторов/приложений должны быть настроены самим владельцем; эта задача их не меняла.
