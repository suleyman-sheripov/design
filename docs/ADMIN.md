# Админка портфолио

Вход — `/design/admin/` или ссылка «Управление сайтом» внизу страницы.

## Первый вход на GitHub Pages

Сначала опубликуй новую версию кода через существующий workflow Deploy to GitHub Pages из `main`. Затем контентные изменения не требуют пересборки.

1. В аккаунте `suleyman-sheripov` открой Settings → Developer settings → Personal access tokens → Fine-grained tokens.
2. Выбери **Only select repositories → design**, срок действия и **Repository permissions → Contents: Read and write**. Остальные права не нужны; Metadata read добавляется GitHub.
3. Введи токен непосредственно в админке. Не присылай его в переписку. Токен живёт только в памяти вкладки, не сохраняется в localStorage, предпросмотре или репозитории. После закрытия страницы нужен повторный вход.

[Официальная инструкция GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

Редактор проверяет логин через GitHub `/user`: он должен совпадать с владельцем. Затем проверяет право записи. На публичном GitHub Pages HTML формы входа открыт. Настоящая защита записи — разрешения GitHub; клиентская проверка логина не отменяет прямой доступ соавторов к репозиторию. Для режима «только я» не выдавай другим аккаунтам и приложениям права записи. Закрытая серверная сессия потребовала бы отдельного сервера. Черновики в публичном репозитории скрыты из подборки, но не являются секретными файлами.

## Возможности

- **Страница и стиль:** заголовки секций, кнопки Hero, обе строки контактов, печатающийся текст, кнопка письма, ссылка на резюме, строка инструментов. Основные цвета, скругления 0–40 px, оформление превью. Отдельные переключатели опыта, услуг/тегов Hero и ленты.
- **Услуги:** добавление, удаление, порядок, название, описание, группа и показ в тегах Hero.
- **Проекты:** добавление, удаление, порядок, черновик/публикация, дублирование в черновик, все тексты и три раздела описания. Цвета карточки, вписывание/обрезка и точка фокуса.
- **Изображения:** превью в подборке (`cover`) и первое изображение кейса (`caseCover`) загружаются отдельно от галереи. Пустое `caseCover` использует превью. Галерея поддерживает замену каждого снимка, подпись, порядок и удаление. Удаление снимка из галереи сохраняет выбранную обложку. Для новых файлов создаются уникальные имена.
- **Профиль и опыт:** имя, профессия, почта, телефон, город, соцсети; места работы, сроки, роли, описания и порядок.
- **Правки:** предпросмотр с новыми картинками, отмена последних 60 операций, экспорт/импорт JSON, резервная копия новых WebP, ссылка на историю GitHub. Конфликт ветки останавливает сохранение без принудительной перезаписи.

Авторский логотип, физика интро, шрифтовая система, произвольная структура секций и SEO-разметка остаются в исходниках. Произвольный HTML/CSS из редактора не исполняется.

## Предпросмотр и сохранение

«Предпросмотр» открывает отдельную вкладку с текущим черновиком, включая новые изображения; обычный сайт не меняется. Не закрывай редактор до просмотра новых картинок: их временные адреса существуют в браузере.

«Сохранить» отправляет JSON и используемые новые изображения одним коммитом в `main`. Публичный сайт читает этот контент из GitHub. Кеш может задержать обновление на несколько минут. Если ветка изменилась, скачай копию и перечитай содержимое; сохранение не перезапишет чужие коммиты.

Автоматического сохранения на диск нет. При закрытии с правками появляется предупреждение. Экспорт JSON не содержит бинарные изображения: новые WebP скачиваются отдельно. Импорт заменяет черновик после подтверждения; отсутствующие снимки нужно загрузить заново. Удалённые из галереи файлы физически остаются в репозитории, чтобы не ломать старые ссылки.

На localhost доступен **локальный черновик без публикации**. Он читает локальную копию, даёт предпросмотр и скачивание файлов, но не записывает в GitHub или исходники. Обычный вход с токеном даже на localhost сохраняет в настроенную ветку GitHub.

Загрузки: PNG/JPEG/WebP до 20 МБ и 40 мегапикселей, до 12 файлов за раз. Изображения конвертируются в WebP до 2000 px по длинной стороне. За сохранение — до 20 МБ подготовленных файлов. SVG и анимированные форматы не принимаются.
