# Следующий этап: галерея проекта в живом инспекторе

Продолжай в ветке claude-live-editor-bridge. Проверенный дифф предыдущего этапа — 9a213e9 поверх 5fe30de. Сначала проверь актуальный HEAD и состояние рабочей копии; сохрани любые незакоммиченные изменения. Не откатывай новые коммиты, не используй force push, main и публикацию не трогай.

## Небольшая доводка предыдущего этапа

Ведущий разработчик прочитал дифф 9a213e9; повторный полный запуск твоих 75 тестов он не выполнял. Направление реализации принято. До повторного использования команд в галерее закрой три конкретных момента:

1. clearAsset сейчас может очистить любой слот, который принимает resolve, включая обязательное cover и file в галерее. Ограничь команду явно поддерживаемым необязательным caseCover. Удаление элемента галереи должно быть отдельной командой удаления вхождения, а не превращать shot.file в undefined. Добавь проверку, что clearAsset с cover/gallery не меняет данные и историю.
2. Тест «раздельные записи Undo для cover и caseCover» считает вызовы touch, а не выполняет Undo. Дополнительно используй настоящую createHistory: назначение cover → назначение caseCover → сброс caseCover → три Undo → три Redo. Проверяй данные на каждом шаге и отсутствие отдельного caseCover в сериализованном JSON после сброса. В тесте clearAsset используй устойчивый объект проекта: нынешняя заглушка findProject создаёт новый объект при каждом вызове и не проверяет итоговую мутацию.
3. «Использовать превью» вызывает полный render, пересоздавая нажатую кнопку, которая затем становится disabled. После этого переводи фокус на актуальную кнопку «Заменить» в блоке обложки кейса. Проверь клавиатурой.

## Реализуй один законченный срез галереи

В инспекторе выбранного проекта добавь блок «Галерея кейса»: упорядоченные миниатюры, понятное пустое состояние и «Добавить изображение». На каждом элементе — «Заменить», «Выше», «Ниже», «Убрать из галереи». Укажи номер изображения в доступном имени кнопок, чтобы одинаковые действия различались для скринридера. Повторное использование одного файла в нескольких местах разрешено.

Добавление и замена используют существующий медиадиалог: выбор существующего изображения или загрузка одного нового файла. Обложки cover/caseCover эти действия не меняют. При удалении убирается только вхождение из shots; бинарный файл не удаляется ни из GitHub, ни из uploads, если он нужен истории или другим местам. Фокус после перестановки остаётся на перемещаемом элементе; после удаления — на соседнем или на «Добавить изображение», если список пуст.

### Идентичность и старый JSON

У каждого вхождения shots нужен устойчивый id. Имя файла и индекс не подходят: один файл может повторяться, а порядок меняться во время обработки загрузки.

Нормализуй отсутствующие id один раз на границе загрузки/импорта документа, ДО начального снимка истории, и присваивай новый id при добавлении/дублировании вхождения. Повторный render, Undo/Redo и переименование проекта не должны создавать новые id. Старый JSON без id должен читаться. Проверь уникальность id внутри проекта; не допускай неоднозначной адресации. Обнови необходимые типы/валидацию, не превращая старый формат в ошибку. Если нормализация меняет состояние относительно сохранённого файла, учитывай это последовательно в saved/dirty.

### Команды и асинхронность

Одна модель данных, существующая история, существующий мост. Команды должны получать projectId + galleryItemId, находить актуальный объект перед мутацией, а не удерживать старый объект или индекс через await. Результаты — тот же явный status, что у текущих медиа-команд.

Загрузка замены: перестановка элемента во время обработки сохраняет правильную цель; удаление цели, Undo/Redo, импорт или закрытие диалога аннулирует устаревший результат. Новый выбор для той же цели побеждает старый. Для добавления не создавай пустую запись shots до успешной подготовки изображения; при отмене не должно остаться пустышки, новой записи истории или неиспользованного upload. Фиксируй незавершённый текст непосредственно перед атомарной мутацией. Одна перестановка/замена/добавление/удаление — один шаг Undo. Без повторной пересылки Blob при каждом символе текста.

Старая форма остаётся доступной: её добавление, дублирование, удаление и перестановка не должны нарушать id и синхронизацию инспектора. Проверь все места создания shots, а не только новый интерфейс.

## Критерий завершения

Проверь реальными данными и настоящей историей:

- Старый JSON; два вхождения одного файла с разными id.
- Добавление, замена, удаление, перестановка; раздельные Undo/Redo.
- Удаление/перестановка цели во время загрузки; отмена диалога; запоздалая ошибка.
- Cover/caseCover остаются прежними.
- Изменения галереи видны на открытой странице кейса в iframe; после сериализации и повторного чтения сохраняются порядок и изображения.
- Работа клавиатурой и узкий экран. Для 390 px сначала подтвердить фактическую ширину viewport, затем проверять переполнение; искажённый снимок или одна проверка scrollWidth сами по себе не доказывают удобство интерфейса.

Запусти штатные тесты, tsc/build, lint, check:content. Браузерные проверки перечисли честно, отдельно от изолированных тестов. Если чего-то не проверил — укажи это.

В этом этапе НЕ нужны массовые загрузки, drag-and-drop сортировка, обрезка, отдельные настройки fit/position, IndexedDB или новая система авторизации. Сначала удобная работающая галерея с кнопками перестановки.

Сделай небольшой коммит доводки и отдельный коммит галереи, отправь в рабочую ветку и дай SHA. После выполнения этих критериев остановись для ревью; не начинай бесконечную косметическую чистку.
