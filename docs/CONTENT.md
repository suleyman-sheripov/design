# Работы и изображения

## Через админку

Полная инструкция по входу, безопасности, отдельным обложкам и настройкам страницы: [Админка портфолио](ADMIN.md).

## Подготовка материалов

Обложка: **1600 × 1000 px (16:10)**, без мелкого текста по краям. По умолчанию изображение показано целиком; обрезку можно включить в редакторе. Сам макет на обложке должен читаться в карточке шириной 280–540 px. Для вертикальных интерфейсов удобно собрать несколько экранов на одном спокойном поле, а детали приложить отдельными снимками.

Детали: **до 2000 px по длинной стороне**, WebP, обычно 150–600 КБ. Длинный лендинг раздели на несколько экранов, чтобы шрифт не стал микроскопическим после уменьшения. Цветовой профиль sRGB. Упаковка — общий вид и отдельная деталь, интерфейс — ключевой сценарий и UI-кит. Не добавляй выдуманные результаты, чужие макеты или сведения, которые нельзя показывать.

Админка принимает PNG, JPEG, WebP до 20 МБ и 40 мегапикселей, уменьшает длинную сторону до 2000 px и экспортирует WebP с качеством 0,88. За одну загрузку — до 12 снимков, за одно сохранение — до 20 МБ подготовленных изображений. SVG и анимированные форматы не принимаются.

## Просто положить файлы

Подготовлены папки и подписи:

| Папка | Обязательно | Дополнительные файлы |
|---|---|---|
| `materials/donerio/` | `cover.webp` | `01-posters.webp`, `02-lightbox.webp`, `03-social.webp` |
| `materials/dr-green/` | `cover.webp` | `01-identity.webp`, `02-package.webp`, `03-detail.webp` |
| `materials/pro-it/` | `cover.webp` | `01-program.webp`, `02-lesson.webp` |
| `materials/billions-lottery/` | `cover.webp` | `01-flow.webp`, `02-screens.webp`, `03-ui-kit.webp` |

Сверь подписи в `images.json` с реальными снимками. У Pro IT нужны собственные учебные материалы, без персональных данных учеников. Год в черновиках намеренно не придуман; можно указать его в редакторе после уточнения.

```sh
npm run import:cases --prefix app
```

Импорт копирует готовые WebP до 3 МБ в `content/work/`, даёт им имена с хешем содержимого и заполняет галереи найденных проектов. Отсутствующие дополнительные снимки пропускаются. Статус остаётся черновиком. Чтобы сразу подготовить публикацию, используй `npm run import:cases --prefix app -- --publish`, затем проверь локально и отправь только `content/` в `main`. Исходники в `materials/` игнорируются Git.

Для правки уже опубликованного кейса через импорт положи в папку **весь нужный набор**: галерея заменяется найденными файлами. Снимки остальных проектов не меняются. Если удобнее видеть результат перед сохранением — используй админку.

## Где источник

`content/data/site.json` содержит `profile` и `projects.projects`. Один JSON нужен для согласованного чтения: профиль и кейсы не могут приехать из разных коммитов. Изображения лежат в `content/work/`. Именно эти пути читает сайт и правит редактор.

Production читает публичный GitHub без токена; это возможно, потому что репозиторий публичный. При ошибке сети или невалидном JSON сайт берёт копию из последней сборки и явно сообщает об этом. Такая копия может быть старее контентных правок. После крупного обновления владелец может вручную запустить Deploy to GitHub Pages, чтобы обновить и резервную копию.

`app/public/content/` и `app/dist/content/` создаются автоматически. Править их бессмысленно: следующая подготовка заменит содержимое. Для ручных локальных изменений JSON при запущенном Vite выполни `node app/scripts/content.mjs --copy` или перезапусти dev-сервер.

## Описание внутри кейса

В редакторе у каждой работы есть «Коротко о проекте» и три отдельных поля: «Задача», «Решение», «Детали проекта». Первое — прежнее краткое вступление; остальные формируют развёрнутый рассказ внутри страницы проекта. Абзацы разделяются пустой строкой.

Пока одно из трёх полей пустое, сайт показывает в этом блоке рыбу с подписью «Текст для примера». После заполнения поля она автоматически заменяется вашим текстом, а подпись исчезает. Рыба не записывается в содержимое проектов и не выдаётся за фактическое описание работы.

В JSON используются необязательные поля `story.task`, `story.solution`, `story.details` внутри проекта в `content/data/site.json`. Старые записи совместимы. Задача и решение расположены перед галереей; детали — после первого большого изображения или первой пары вертикальных экранов.
